# 3장 - 명령어
컴퓨터는 여러 명령어를 처리하는 기계일 뿐임. 
그 명령어들에는 어떤 것이 있고, 어떻게 처리하는지 깊게 알아보자.
---
### 고급 언어 vs 저급 언어

- 고급언어
  - 사람을 위한 언어
  - 프로그래밍 할 때 쓰는 보편적인 언어(Cpp, Py, Java)
- 저급언어
  - 컴퓨터가 직접 이해하고 실행할 수 있는 언어
  - 기계어
    - 01010 식의 비트로 이뤄짐
    - 보통 길어지니까 16진수로 표현. 21e8, 47f9
  - 어셈블리어
    - 기계어를 읽기 편한 형태로 번역한 언어


### 컴파일 언어 vs 인터프리터 언어
- 컴파일 언어
  - 컴파일러에 의해 소스 코드 전체가 저급 언어로 변환되어 실행되는 고급 언어
  - 처음부터 끝까지 소스코드를 목적 코드로 훑으며 바꾸기에 오류가 하나라도 발생하면 컴파일 실패 -> N번째 줄에 문제가 있더라도 N-1줄 까지는 실행
- 인터프리터 언어
  - 소스코드가 한 줄씩 실행되는 고급 언어
  - 대표적으로 Python이 있음
  - 한줄씩 실행하기에 오류 전까지는 실행됨.

### Py나 Java 등 현대의 많은 언어는 컴파일과 인터프리터를 동시에 수행함(개념적인 구분을 하자)

### 링킹
- 여러 개의 컴파일된 파일을 라이브러리를 하나로 연결하는 작업
- 출력 라이브러리가 있어야 print를 할 수 있고, 수학 관련 라이브러리를 링킹 해줘야 add() 할 수 있다.

전체적인 흐름을 정리하면 아래와 같겠다.
```text
사람이 작성
│
▼
C 소스코드 (.c)
│
Compiler (컴파일러)
│
▼
Assembly (.s)
│
Assembler (어셈블러)
│
▼
Object File (.o)
│
Linker (링커)
│
▼
실행 파일 (.exe, a.out)
│
▼
CPU가 실행
```

## Why?? 굳이 컴파일 -> 어셈블리어 -> 기계어 과정을 거쳐야할까?

C언어 소스코드를 바로 기계어로 바꿔주면 중간에 과정하나 생략되고 좋은 거 아닌가? 라는 의문이 듦

답변: **CPU마다 기계어가 다르다.** x86, ARM 둘다 기계어 인식 하는 방식이 다름.

CPU 회사마다 기계어 인식 방식을 다 다르게 하더라도, 개발자들이 편하게 개발할 수 있는 일종의 추상화 계층이라고 받아들여진다.(C언어 말고도 다양한 언어가 이래서 나올 수 있지 않았나 싶다)

Assembly는 CPU별 **공용 언어** 역할이라고 표현한다.

### 어셈블리어 형식
- 연산 코드 | 피연산자(오퍼랜드 라고 부름)
  - ex. 아래와 같은 식으로 씀
    - push rbp
    - mov rbp, rsp
    - pop rbp
- 보통 오퍼랜드에 값 자체를 쓰는 것이 아니라 그 데이터가 저장된 메모리 주소나 레지스터 이름이 담김.
  - 오퍼랜드 필드 안에 주소가 담긴다면 메모리나 레지스터가 저장할 수 있는 정보의 가짓수 만큼 커질 것임. 
  - 만약 많은 값을 나타내야 하는데 명령어에 다 표현하면 너무 길어지거나 표현이 힘들어짐
