# Chapter 09 - 1

1장부터 8장까지는 컴퓨터 부품에 대한 것과 프로그램이 어떻게 실행되는지에 대해서 알아봤다. 이제부터는 운영체제에 대해서 배운다.

**운영체제**

- 실행할 프로그램에 필요한 자원을 할당하고, 프로그램이 올바르게 실행되도록 돕는 특별한 프로그램
- 응용프로그램과 하드웨어 사이에서 응용프로그램에 필요한 자원을 할당하고 응용 프로그램이 올바르게 실행되도록 관리하는 역할

`운영체제 또한 여느 프로그램과 마찬가지로 메모리에 적재되어야합니다.` 라고 책에 나와 있다.

> Q. 그러면 운영체제를 누가 메모리에 올려주는걸까? 이렇게 자원을 올리고 내리는 프로그램이 운영체제인데 운영체제를 움직일수 있게 하는건 누굴까?
>

> A. 운영체제도 결국 파일일 뿐이고 그걸 처음 메모리에 올려서 실행하는건 부트로더(Bootloader)라는 별도의 작은 프로그램이다.
>

Bootloader를 통해 운영체제를 메모리에 적재하고 실행하는 과정

```notion
1. 전원 켜짐
2. CPU가 ROM(BIOS)의 코드를 실행
3. BIOS가 디스크에서 부트로더를 RAM에 복사, 실행함
4. 부트로더가 디스크에서 운영체제 즉 커널을 RAM에 복사함
5. CPU가 이제 운영체제 코드를 실행하게 됨
```

1: 전원을 처음 킨 순간에는 RAM에 아무것도 적재되어있지 않음. 완전히 빈 상태

2: CPU는 전원이 켜지면 항상 정해진 주소부터 코드를 읽도록 설계되어 있다. 이건 소프트웨어가 아니라 하드웨어 자체가 이렇게 만들어져 있음. 그런데 항상 정해진 주소를 읽는데 이게 ROM안에 있는 BIOS임.

→ 즉 CPU가 제일 먼저 보는곳은 RAM이 아니라 ROM이기 때문에 CPU가 ROM의 코드를 실행한다.

3: BIOS가 하는 일은 딱 하나 Bootloader라는 작은 프로그램을 디스크에서 찾아와서 RAM에 복사하고 실행

4: Bootloader가 하는 일은 디스크에 있는 운영체제(커널) 파일을 통째로 RAM에 복사함.

5: 복사가 끝나면 CPU는 이제 그 복사된 운영체제 코드부터 시작하게 됨 → 여기서부터 진짜 운영체제가 실행되는 시점

# Chapter 09 - 2

**커널**

- 자원에 접근하고 조작하는 기능, 프로그램이 올바르고 안전하게 실행되게 하는 기능, 운영체제의 핵심 서비스

**사용자 인터페이스** - 윈도우의 바탕화면과 같이 사용자가 컴퓨터와 상호작용 할 수 있는 통로

- 그래픽 유저 인터페이스
- 커맨드 라인 인터페이스

가상머신 - 소프트웨어적으로 만들어낸 가상 컴퓨터

`가상화를 지원하는 CPU는 커널 모드와 사용자 모드 이외에 가상머신을 위한 모드인 하이퍼 바이저 모드를 따로 둡니다.` 라고 책에 나와있다.

> Q. 그러면 하이퍼 바이저는 OS랑 같이 적재되는건가? 즉 책에서 나온 진짜 OS인 윈도우를 적재할때 같이 되는건가?
>

> A. 결론부터 말하면 적재되는 개념이 아니다. 하이퍼 바이저는 적재되는게 아니라 CPU안에 원래 내장되어 있는 하드웨어 기능이다. 그러나 평소에는 꺼져 있는 상태이다. 그래서 가상 머신을 사용하고 싶으면 하이퍼 바이저를 활성화 시켜야 하는데 이 활성화 시키는 프로그램이 **VirtualBox**라는 프로그램이다.
>

하이퍼 바이저 모드를 활성화하는 VirtualBox의 실행 과정

```notion
1. CPU는 처음부터 하이퍼바이저 모드 기능을 갖고 있음 (평소엔 비활성 상태)
2. VirtualBox를 다운로드/설치
3. VirtualBox 실행
4. VirtualBox가 CPU한테 하이퍼바이저 모드를 활성화 하는 명령을 보냄 -> **VMXON**이라는 명령
5. 그 순간부터 CPU의 하이퍼바이저 모드가 활성화됨
6. 이제 VirtualBox가 그 위에서 게스트 OS(리눅스 등)를 안전하게 실행시킬 수 있음
```

> Q. 하이퍼 바이저 모드를 활성화 하는 VirtualBox가 없으면 하이퍼 바이저가 안되나?
>

> A. 당연한 소리겠지만 활성화가 안된다. 그러나 VirtualBox말고도 VMware, Hyper-V, WSL2, Docker Desktop 이런 프로그램들이 있다.
>

**가상머신과 VT - X**

> Q. 책을 기반으로 컴퓨터 하나에서 윈도우랑 리눅스를 동시에 사용하고 싶을때 가상머신 속 리눅스는 자기가 진짜 주인이라고 생각하며 하드웨어한테 직접 명령을 내릴텐데 그러면 진짜 OS인 윈도우랑 충돌나지 않을까?
>

> A. 충돌이 안나도록 CPU가 중간에서 게스트OS(리눅스)를 속이는 구조로 설계가 되어 있다. 여기서 핵심은 리눅스한테는 가짜 세상을 하나 통째로 주고 진짜 자원은 하이퍼바이저가 관리한다.
>

**VT-X의 지원을 받아 가상 머신이 동작하는 과정**

```notion
1. 리눅스 즉 게스트OS 는 자기가 이 컴퓨터의 진짜 주인인 것처럼 착각한 채 실행됨
2. 리눅스가 평소처럼 코드를 실행 (대부분의 계산/메모리 작업은 그냥 그대로 실행됨)
3. 리눅스가 하드웨어를 직접 건드리는 위험한 명령을 내리는 순간 CPU가 가로챔
4. CPU가 그 요청을 하이퍼바이저(진짜 관리자)한테 넘김
5. 하이퍼바이저가 대신 처리하거나, 진짜 자원과 매핑해서 안전하게 넘겨줌
6. 처리 끝나면 다시 리눅스한테 결과를 돌려주고 실행을 이어감
```

2~3: 모든 명령을 가로채는 게 아니라, **하드웨어를 직접 건드리는 특권 명령어만** 가로챈다. 나머지 대부분의 연산은 평소처럼 실행된다.
**특권 명령 - CPU가 커널 모드에서만 실행을 허락하는 특별한 명령어. 하드웨어 직접 제어, 인터럽트 설정 등이 여기 해당한다. 사용자 모드에서 실행하려고 하면 CPU가 거부한다.**

4~5: 하이퍼바이저가 처리하는 대표적인 예시가 메모리 주소 문제다. 리눅스한테는 진짜 물리 메모리 주소를 절대 주지 않고 가짜 메모리 공간을 하나 만들어서 준다.

**여기서 VT - X의 기술은 하드웨어를 직접 건드리는 위험한 명령을 CPU가 가로채가는 기술이다.**

> Q. 그러면 가로채간 명령어는 사라지는거야?
>

> A. 명령어가 사라지거나 무시되는게 아니라 대신 처리해줄 하이퍼 바이저에게 넘겨져서 결국에는 처리된다.
>

**가로채간 명령어가 처리되는 과정**

```notion
1. 리눅스가 위험한 명령(ex: 특권 명령)을 실행하려는 순간 CPU가 즉시 실행을 멈춤 -> VM Exit(리눅스가 실행되던 세계에서 빠져나옴)
2. CPU실행 권한이 하이퍼 바이저에게 넘어감. 이때 CPU가 왜 멈췄는지에 대한 정보를 같이 넘겨줌
3. 하이퍼 바이저가 그 명령어가 뭘 하려는건지 확인하고 두가지중 선택해서 처리함.
	- 직접 대신 실행: 예를 들어 리눅스가 진짜 디스크에 데이터를 써달라고 요청을 하면 하이퍼 바이저가 안전하게 확인한 뒤에 실제 하드웨어에게 그 작업을 대신 해줌
	- 가짜 값으로 응답: 예를 들어 리눅스가 CPU정보를 요청하면 진짜 정보 대신에 하이퍼 바이저가 리눅스한테 가상 하드웨어 스펙(가짜 정보)를 줌
4. 처리가 끝나면 CPU는 다시 리눅스를 실행으로 복귀한다. -> VM Entry 이때 리눅스는 자기가 멈춰 있다는 것 조차 눈치를 못챔 즉 자기가 정상적으로 실행한 것 처럼 느끼면서 계속 다른 것도 실행
```
