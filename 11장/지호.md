# 11장

## 11-1

프로세스들은 모두 자원을 필요로함.
자원들은 한정되어 있기 때문에 자원들을 프로세스에게 잘 배분해야함.

CPU스케줄링: 프로세스들에게 CPU자원을 배분하는것.

프로세스에게 어떻게 공평하게 자원을 배분하는것인가?

우선순위를 따라서 배분함.

우선순위가 높은 프로세스는 보통 입출력 작업이 많은 프로세스가 우선순위가 높음.
우선순위는 PCB에 기록 됨.

많은 프로세스가 자원을 이용하기를 원하는데 이것을 **스케줄링 큐**로 관리함.

준비 큐와 대기 큐가 존재하는데 준비 큐는 CPU를 사용하기 위한 큐 이고
대기큐는 입출력 장치를 이용하기위한 큐 임.

프로세스중에는 더 급한 프로세스가 끼어 들수있는 선점형 스케줄링과 비선점형 프로세스가 있음.

선점형은 자원을 더 많은 프로세스에 골고루 할당이 가능하지만 문맥교환이 발생함에 따른 오버헤드 가 생기고

비선점형은 자원이 한프로세스에 더 오래 머물기 때문에 자원이 정체 되어있는 시간이 더 많음 하지만 문맥교환이 없기때문에 오버헤드가 발생하지 않는다.

## 질문 
우선순위가 무엇이고 어떤식으로 해석되는것인가?

![alt text](image.png)


선점형 스케줄링과 비선점형 스케줄링을 선택해서 사용할수 있는것인가? 아니면 원래 정해저서 바꿀수 없는것인가?

운영체제와 스케줄링 정책에 따라 결정됨. 하나의 운영체제에서도 여러 스케줄링 정책이나 스케줄러를 사용할 수 있다.


선점형 스케줄링의 선점하는 프로세스의 기준은 우선순위인것인가?


우선순위가 기준이 될 수 있지만, 선점형 스케줄링의 선점 기준이 항상 우선순위인 것은 아니다.
스케줄링 정책에 따라 다르다.


컴퓨터에서 작업 관리자에서 우선순위를 바꿀수 있던데 그럼 작업 속도가 더 빨라지나?

우선순위를 높인다고 CPU 자체가 빨라지는 것은 아니다.

CPU 사용률이 100% 여러 프로세스가 CPU 경쟁  
→ 우선순위 ↑  
→ 해당 프로세스가 CPU를 더 우선적으로 할당받음  
→ 작업이 빨라질 수 있음
