교착 상태 검출 후 회복

> Q. 결국에는 교착 상태를 해결하기 위해서는 어떤 방법을 사용해야지 가장 잘 사용할 것 일까?
>

> A.  결론부터 말하자면 상황에 따라서 방법을 다르게 사용해야한다.
>

**일반 OS같은 경우(윈도우, 리눅스 같은 범용 운영체제)** - 대부분 무시(타조 알고리즘)를 사용한다. 실제로 일반 사용자와 프로세스들끼리 교착 상태가 일어나는 경우도 드물고 이걸 막으려고 다른 방법을 사용하면 오히려 오버헤드가 손해

**데이터 베이스** - 검출 후 회복 방법을 사용함. 트랜잭션끼리 락이 자주 충돌하고 데이터 정합성이 걸린 문제라 무시할 수가 없음. 그래서 wait-for 그래프로 주기적으로 감시하다가 걸리면 롤백시킨다.

```notion
데이터 정합성: 데이터가 앞뒤가 안 맞는 이상한 상태 없이, 항상 올바르고 일관된 상태를 유지하는 것
wait - for 그래프: 자원 할당 그래프를 단순화 한 그래프. 자원 노드를 아예 빼버리고 그냥 화살표로 표시만 함 즉 A가 B자원을 기다린다를 프로세스  A -> B 이렇게만 표한함 
```

**실시간/ 임베디드 시스템(공장 로봇 제어, 항공기 제어 소프트웨어쪽 등)** - 예방 회피 방법을 선호함. 혹시 모를 상황이 아니라 아예 절대 일어나면 안되는 시스템이기 때문에 오버헤드 손해를 감수 하고도 안전 상태를 최 우선으로 확인
