# Chapter 14 - 1

연속 메모리 할당 - 프로세스에게 연속적인 메모리 공간을 할당하는 방식

스와핑 - 오랫동안 사용되지 않은 프로세스를 임시 보조기억장치 일부 영역으로 쫒아 내고 그렇게 해서 생긴 메모리상의 빈공간에 또 다른 프로세스를 적재하여 실행하는 방식

- 스왑인
- 스왑 아웃
- 스왑영역

메모리 공간에 프로세스를 연속적으로 할당하는 방식

- 최초 적합(frist fit)
- 최적 적합(best fit)
- 최악 적합(worst fit)

연속 메모리 할당의 첫 번째 단점 → 외부 단편화 발생

외부 단편화 - 프로세스를 할당하기 어려울 만큼 작은 메모리 공간들로 인해 메모리 낭비가 되는 것

→ 해결방법: 압축(단점이 너무 많음), 가상메모리 기법 중 페이징 기법(현대에서도 사용하는 중)

> Q. 최악 적합은 제일 안좋은 것 같아보이는데 굳이 이렇게 이름까지 정해둘 필요가 있을까?
>

> A. 최악 적합이 이름만 들으면 제일 안 좋은 방법처럼 보이지만 사실 의도가 있다. 최적 적합처럼 딱 맞는 작은 공간에 넣으면 남는 자투리가 너무 작아서 아무도 못쓰는 죽은 공간이 되기 쉬운데 최악 적합은 일부로 가장 큰 공간에 넣어서 남는 자투리도 크게 유지시켜서 나중에 다른 프로세스가 그 자투리를 재활용 할 수 있게 하려는 전략이다. 즉 지금 당장은 최선은 아니지만 장기적으로 덜 낭비 되게 하여 노린 것 이다.
>

# Chapter 14 - 2

연속 메모리 할당의 두번째 단점 → 물리메모리보다 큰 프로세스를 실행 할 수없음

가상 메모리 관리 기법 - 실행하고자 하는 프로그램을 일부만 메모리에 적재하여 실제 물리 메모리 크기보다 더 큰 프로세스를 실행할 수 있게 하는 기술

→ 페이징, 세그멘테이션

페이징 - 메모리와 프로세스를 일정한 단위로 자루고 이를 메모리에 불연속적으로 할당할 수 있게 하는 기법

- 페이지 - 페이징의 단위
- 프레임 - 메모리 물리 주소 공간

페이지 테이블(page table) - 페이지 번호와 프레임 번호를 짝지어 주는 일종의 이정표

- 페이지 테이블 베이스 레지스터(PTBR) - 각 프로세스의 페이지 테이블이 적재된 주소를 가리킴

페이징 → 외부 단편화 해결, 내부 단편화 발생

세그멘테이션 → 외부 단편화 발생, 내부 단편화 해결

페이지 번호 - 접근하고자 하는 페이지 번호

변위 - 접근 하려는 주소가 프레임의 시작 번지로부터 얼만큼 떨어져 있는지 알 수 있음

논리주소 - 페이지 번호, 변위

물리주소 - 프레임 번호, 변위

페이지 테이블 엔트리

- 유효 비트
- 보호 비트
- 참조 비트
- 수정 비트

페이징의 장점 → 쓰기 시 복사(copy on write) - 프로세스 간 자원 공유 가능

> Q. 책에는 설명을 안해주는데 세그먼테이션은 뭘까?
>

> A. 페이징은 똑같은 크기로 나눴다면 세그멘테이션은 의미 있는 단위로 자른다.
>

코드 영역, 데이터 영역, 스택 영역 → 이렇게 각자 나눈 논리적 단위를 **세그먼트**라고 부름

페이지 테이블 처럼 세그먼트 테이블이 존재함. → 세그먼트 번호는 물리 메모리 몇번지부터 시작해서 길이를 알려줌

그러나 여기서 문제 → 세그먼트는 페이지와 달리 크기가 제각각이라서(코드 50kb, 데이터 20kb 등등)이걸 메모리에 배치를 하다보면 외부 단편화가 생긴다. → 즉 방식이 연속 메모리 할당과 비슷해서 외부 단편화 문제가 발생

> Q. 페이징은 내부 단편화 문제가 발생하고 세그멘테이션은 외부 단편화 문제가 발생하는데, 둘을 합쳐서 쓰면 해결되지 않을까?
>

> A. 맞다. 실제로 이 아이디러를 그대로 실현한 **세그먼트 페이징** 이라는 하이브리드 방식이 있다.
>

세그먼트 페이징 - 먼저 프로세스를 세그멘테이션 처럼 의미 있는 단위(코드/데이터/힙/스택)로 나누고 그 세그 먼트 하나하나를 다시 페이징 처럼 고정 크기 페이지로 잘라서 관리한다. → 그러나 이러면 외부 단편화는 해결 되지만 내부 단편화는 페이지 자투리 만큼 아주 조금 남는 내부 단편화를 완벽히 해결하진 못한다. 그러나 이정도는 무시할 만한 수준이라 두 문제를 해결한 셈이다.

다만 오늘날은 이 방식 대신에 그냥 순수페이징만 사용한다.

# Chapter 14 - 3

요구 페이징 - 프로세스에 메모리를 적재할 때 처음부터 모든 페이지를 적재하지 않고 필요한 페이지만 메모리에 적재하는 방식

- 순수 요구 페이징

페이지 교체 알고리즘

- FIFO 페이지 교체 알고리즘
- 최적 페이지 교체 알고리즘
- LRU 페이지 교체 알고리즘

스래싱 - 프로세스가 실제 실행되는 시간보다 페이징에 더 많은 시간을 소요하여 성능이 저해됨

멀티프로그래밍 정도 - 메모리에서 실행되는 프로세스의 수

프레임 할당 방식

- 정적 할당 방식 - 균등 할당, 비례 할당
- 동적 할당 방식 - 작업 집합 모델, 페이지 폴트 빈도

작업 집합 -  실행 중인 프로세스가 일정 시간 동한 참조한 페이지의 집합

> Q. 스래싱이 심해지면 CPU 이용률이 뚝 떨어진다고 했는데 이걸 그냥 두면 시스템 전체가 멈춰버리는거 아닌가? 운영체제가 이걸 막을 방법이 있을까?
>

> A. 막을 수 있다. 리눅스에는 OOM Killer(Out-Of-Memory Killer)라는 기능이 있는데 스래싱 위험이 커지만 시스템이 자동으로 메모리를 제일 많이 먹는 프로세스를 강제 종료 시켜버림 → 운영체제의 응급 대응책 그러나 정말 최후의 수단이라 책에 나온 것 처럼 작업 집합 모델이나 페이지 폴트 빈도를 기반으로 프레임을 잘 배분하는게 우선이다.
>
