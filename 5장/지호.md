## 빠른 CPU를 만드는 설계 기법들
### 클럭속도를 올리는 방법  

클럭: CPU의 속도 단위.  

클럭의 성능을 높이면 CPU의 성능이 좋아지는것은 맞지만 발열문제 때문에 한계가 존재한다.

### 코어와 스레드 수를 늘리는 방법

코어: 명령어를 실행하는 부품 (ALU, 제어장치, 레지스터)를 포함한다.  

이것들을 여러개 포함하면 멀티코어라고 부른다.

스레드: 실행 흐름의 단위

하드웨어적, 소프트웨어적 스레드가 구분된다.

하드웨어적 스레드: CPU가 처리하는 명령어의 단위이다.

소프트웨어적 스레드: 하나의 프로그램에서 독립적으로 실행되는 단위이다.

## 명령어 병렬 처리 기법

### 명령어 파이프 라이닝
명령어 처리과정은 일반적으로  

명령어 인출 - 해석 - 실행 - 결과 저장 단계로 나뉜다. 

명령어 파이프 라이닝: 단계가 겹치지않는것들을 동시에 처리하는것이다.

파이프라이닝 위험 : 특정상황에서 파이프라이닝으로 성능향상이 되지않는경우이다.

데이터 위험, 제어 위험, 구조적 위험 등이 있다.

### 슈퍼 스칼라

슈퍼스칼라: 파이프라이닝을 여러개 사용하는것이다.

### 비순차적 명령어 처리

비순차적 명령어 처리:명령어의 순서를 바꿔도 문제될것이 없는것들에 한해서 순서를 바꿔 실행하는 기법이다.

## CISC 와 RISC
ISA:CPU가 이해할수있는 명령어들의 집합이다.

모든 CPU가 같은 ISA를 공유하지 않는다.

CISC:복잡하고 다양한 기능을 제공하는 ISA를 사용함.

RISC:CISC에 비해 적은 명령어, 짧은 명령어를 사용함.

복잡하고 다양한 명령어를 사용하다 보니 수행시간이 일정하지 않다. 그래서 파이프라이닝에 어려움이 있다.

반대로 RISC는 짧고 규격화 되었기 때문에 파이프라이닝 하기가 쉽다.

비순차적 명령어처리 기법에 대한 질문

데이터 의존성을 파학하는데 걸리는 시간이 더 오래걸리지 않나?

비순차 실행은 데이터 의존성을 분석하는 오버헤드가 존재한다. 하지만 현대 CPU는 전용 하드웨어를 이용해 이 분석을 매우 빠르게 수행하며, 그보다 훨씬 큰 대기 시간(특히 메모리 접근 지연)을 줄일 수 있기 때문에 전체 성능이 크게 향상된다.

SRAM(Static RAM)은 플립플롭 회로를 이용하여 데이터를 저장하는 휘발성 메모리이다.
전원이 공급되는 동안에는 Refresh 없이 데이터를 유지할 수 있어 DRAM보다 매우 빠르다.
하지만 1비트를 저장하는 데 여러 개의 트랜지스터가 필요하여 가격이 비싸고 집적도가 낮다.
따라서 CPU의 L1, L2, L3 캐시 메모리에 주로 사용된다.
