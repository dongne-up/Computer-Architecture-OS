# 5장 - CPU 성능 향상 기법

현대 CPU는 어떻게 효율을 내고 있는가. 그들의 향상 기법을 알아보자.


## 멀티 코어 VS 멀티스레딩

멀티코어 : 하나의 CPU 안에 독립적으로 명령어를 실행할 수 있는 코어를 여러 개 넣은 구조((각 코어는 자신만의 ALU, 레지스터, 제어장치 등을 가짐))

멀티스레딩(Simultaneous Multithreading) : 하나의 물리 코어가 여러 개의 하드웨어 스레드를 제공하여, 운영체제 입장에서는 여러 개의 코어(논리적인)처럼 보이게 하는 기술.


## 명령어 처리기법(Instruction-Level Parallelism)

빠른 CPU를 만드려면 결국 코어(스펙) 안에서 최대한 쉬지 않는 CPU를 만들도록 task를 분리하는 것이 중요.

- 명령어 파이프라인
  - 명령어 하나의 실행 과정을 여러 단계로 나누고, 여러 명령어를 서로 다른 단계에서 동시에 처리하는 기법.
  - 의존성이 있는 데이터나 프로그램 주소의 갑작스런 변화, 동시성 문제 때문에 오히려 기다리거나 꼬인 시간이 늘어날 수 있음.
- 비순차적 명령어 처리
  - 순서를 바꿔도 실행해도 무방한 명령어를 먼저 실행하여 명령어 파이프라인이 멈추는 것을 방지
  - 좀 더 정확히는 실행은 먼저 할 수 있지만 결과는 원래 프로그램 순서대로 commit함.
  - 현대 CPU의 필수 기법


## ISA(Instruction Set Architecture) - 명령어 집합 구조

CPU가 이해할 수 있는 명령어 집합. 회사별로 다름.

현대 ISA에는 크게 두가지가 있음

- CISC(Complex Instruction Set Computer)
  - 다양한 기능을 수행하는 복잡한 명령어를 많이 제공하는 ISA
  - Intel의 x86이 대표적
  - 가변 길이 명령어를 사용하기 때문에 CPU의 복잡한 명령어를 모조리 표현하고 활용할 수 있음
  - 하지만 이런 가변 길이 명령어는 명령어마다 언제 끝날지 모르기에 명령어 파이프라인을 유연하게 사용하기 힘듦.
  - 실제로 자주 쓰는 명령어만 자주 씀
- RISC(Reduced Instruction Set Computer)
  - 말그대로 reduce 된 기법
  - CISC비해 명령어 종류가 적지만 고정 길이 명령어를 사용함. -> 규격화가 되어있음 -> 명령어 파이프라이닝 최적화
  - ARM이 대표적인 RISC ISA이며, Apple Silicon도 ARM ISA를 사용

### 한 코어에 몇개의 하드웨어 스레드를 돌리는게 적절한지?(현재 회사들은 어떤 기준을 갖고 있는지)

Intel : 2-way 멀티스레딩 
AMD : 2-way 멀티스레딩

왜 4개 8개로 안늘리지? -> 멀티스레딩을 논리적으로 구현하려면 그에따라 저장하고 처리해야할 로직이 복잡해진다.

레지스터 파일이 커지고, 스케줄러가 복잡해지고, 소비전력이 증가하고, 캐시 경쟁도 심해진다.

실제로 CPU 제조사에서 아키텍처를 미리 정해서 제품을 만듦. -> 멀티스레팅 효율을 후에 바꿀 수 없음
대용량 서버용은 8-way도 사용
