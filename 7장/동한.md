하드 디스크 = 자기 디스크

- 플래터 – 동그란 원판
- 스핀들 – 플래터를 회전시키는 구성요소
- RPM – 스핀들이 플래터를 돌리는 속도
- 헤드 – 플래터 위에 미세하게 떠 있는 채로 데이터를 씀
- 디스크 암 – 헤드를 원하는 위치로 이동시킴
- 트랙 – 동심원 하나
- 섹터 – 트랙을 부채꼴로 만든 조각
- 실린더 – 각 플래터들의 같은 트랙의 값을 나열한 것
- 단일 헤드 디스크 – 플래터의 한 면당 헤드가 하나씩 달려 있는 하드 디스크
- 다중 헤드 디스크 – 헤드가 트랙별로 여러 개 달려 있는 하드 디스크

>Q. 그러면 요즘에는 단일 헤드 디스크 보다 다중 헤드 디스크를 많이 사용하는건가?

>A. 결론부터 말하자면 요즘에는 단일 헤드 vs 다중 헤드가 아니라 HDD(하드 디스크) >vs SSD이다.

요즘은 노트북이나 일반 사용자 같은 경우는 SSD를 많이 사용하고 SSD는 플레터,
헤드, 회전 같은 기계 부품 자체가 없고 반도체(플래시 메모리)에 전기적으로 저장을
함 그래서 탐색시간이라는 개념이 없음 반면 데이터 센터, 서버, 대용량 백업 / 아카이브 스토리지에서는 여전히 다중플래터 HDD를 사용함

>아카이브 스토리지 – 자주 안쓰지만 오래 보관해야하는 것 ex) cctv기록, 로그파일 등

> Q. 우리나라는 반도체 산업이 되게 뛰어나다고 하는데, 어떤 것 때문에 그런 걸까?

**결론: 반도체 전체가 아니라 "메모리 반도체" 분야에서 세계 최고 수준이다.**

반도체는 크게 두 종류로 나뉨
- 비메모리(시스템) 반도체: CPU, GPU 등 연산용 로직 칩
- 메모리 반도체: D램, 낸드플래시 등 저장용 칩

이 중 우리나라는 메모리 반도체 분야에서 매우 뛰어남

**최근 이슈: SK하이닉스와 HBM**

메모리 반도체 중에서도 D램, 낸드플래시, 그리고 최근 특히 주목받는 HBM(고대역폭 메모리)를 잘 만든다. 
최근 SK하이닉스가 급성장한 이유가 바로 이 HBM이다. AI(챗봇) 붐이 터지면서 GPU에 데이터를 초고속으로 공급해줄 메모리 수요가 폭증했고, SK하이닉스가 이 HBM 시장을 70~80% 점유하며 주도하고 있다.

>구체적으로 어떤 "기술" 때문에 잘 만드는가
1. 미세공정 기술: 회로선 폭을 얼마나 가늘게 새길 수 있는지의 문제다. 선폭이 가늘수록 같은 면적에 더 많은 트랜지스터를 넣을 수 있어, 속도는 빨라지고 전력 소모는 줄어든다.
2. 적층/패키징 기술: HBM은 D램 칩을 여러 층으로 수직으로 쌓아(TSV라는 기술로 층마다 미세한 구멍을 뚫어 전기적으로 연결) 대역폭을 극대화한 메모리다. 이 얇은 칩을 정교하게 쌓아 연결하는 기술이 핵심이다.
3. 대량 양산 수율: 나노미터 단위 초미세 공정에서 불량 없이 대량으로 찍어내는 노하우다. 설계가 좋아도 수율이 안 나오면 상업적으로 의미가 없다.

>트렌지스터 – 전기 신호를 키고 끄는 아주 작은 스위치 반도체 칩안에는 이런게 수십
개가 있는데 트랜지스터가 많으면 많을수록 더 많은 연산을 처리할 수 있음 

>GPU - 그래픽(화면에 그림을 그리는 연산)을 처리하려고 만든 칩이면서 단순한 계산들을 동시에 병렬적으로 처리 가능함
GPU가 연산을 빨리 하려면 → 옆에서 데이터를 빠르게 공급해줄 메모리가 필요함 → 그게 바로 HBM

>TSV(실리콘 관통 전극) - HMB을 만드는 기술인데 말 그대로 실리콘을 관통하는 통로

RAID - 데이터의 안정성 혹은 높은 성능을 위해 여러 개의 물리적 보조기억장치를 마치 하나의 논리적 보조기억장치처럼 사용하는 기술

RAID 종류(책에서 설명한것만)

RAID0 - 여러 개의 보조기억장치에 데이터를 단순히 나누어 저장하는 구성방식

- 스트라입 - 줄무늬처럼 분산되어 저장된 데이터
- 스트라이핑 - 분산하여 저장하는 것

RAID1 - 복사본을 만드는 방식

- 미러링 - 거울처럼 완전한 복사본을 만드는 방식

RAID4 - 오류를 검출하고 복구하기위한 정보를 저장하는 장치를 두는 구성 방식

- 패리티 비트 - 오류를 검출하고 복구하기 위한 정보

RAID5 - 패리티를 한 디스크에 몰아넣지 않고 여러 디스크에 골고루 나눠서 저장

RAID6 - 서로 다른 패리티를 두 개 만들어서 저장

>Q. 그러면 패리티가 하나면 하나의 하드 디스크만 복구가 가능한건가?

A. 맞다. 그런데 패리티 일대일 대응해서 고치는게 아니라 만약 **동시에** 두개의 하드디스크가 고장 나야지 문제가 생김

즉 하드 디스크A 고장 -> 패리티 사용 -> 하드 디스크A복구 -> 하드 디스크B고장 -> 패리티 사용 -> 하드 디스크 B복구 -> 이건 가능함

그런데 하드 디스크 A고장 -> 패리티 사용 -> 하드 디스크B 고장 -> 패리티는 두개중 어떤걸 복구해야할지 모름

>Q. 이러면 하드 디스크 갯수만큼 패리티를 맞춰야하는거 아닌가?

A. 이론적으로 이게 맞다. 그러나 이렇게 하지 않는 이유는

1. 패리티 하나 = 저장공간을 통채로 하나를 날림 -> 저장공간 낭비
2. 하드 디스크 갯수가 정해져 있는데 패리티 갯수를 늘리면 저장할 공간이 없음 즉 디스크 5개 중에 패리티 5개 -> 실제 데이터 저장할 공간 0개 저장 가능 ->저장을 해야하는 장치가 저장을 못함 의미가 없음
3. 데이터를 쓸때마다 패리티도 같이 써야함 -> 쓰기 속도 느려짐
4. 확률적으로 동시에 하드디스크가 망가질 경우는 거의 없음
